# Hello-Agents：30 道人工 RAG 评估题

> 来源：`Hello-Agents-V1.0.2-20260210.pdf`  
> 用途：评估检索是否能找到正确章节与页码。答案用于人工核对，不应直接放入用户查询。  
> 页码均指 PDF 阅读器显示的物理页码，而不是书内印刷页码。

## 使用方法

1. 将问题逐条加入 KUN 的 RAG 实验室。
2. 正确来源文档选择 `Hello-Agents-V1.0.2-20260210.pdf`，并填写表中的预期页码。
3. 先用 `Top K = 5` 运行，观察 Recall@5、MRR、nDCG 与 P95 延迟。
4. 若未命中，先检查 Chunk 是否保留标题与页码，再调整切分、混合检索及 Rerank。

## 评估集

### HA-001｜基础概念｜简单

- **问题**：智能体通过哪些组成部分形成“感知—行动”闭环？
- **参考答案**：智能体通过传感器感知环境，经内部状态与决策形成行动，再通过执行器影响环境；自主性使其能够围绕目标独立决策。
- **预期来源**：第 10 页，第一章 1.1。
- **检索关键词**：传感器、环境、执行器、自主性。

### HA-002｜智能体类型｜中等

- **问题**：简单反射智能体的决策核心是什么，它有什么典型局限？
- **参考答案**：核心是工程师预先设计的“条件—动作”规则；它只依据当前感知做反应，缺乏历史状态、规划与学习能力。
- **预期来源**：第 10 页起，第一章 1.1.1。
- **检索关键词**：Simple Reflex Agent、条件动作规则。

### HA-003｜发展史｜简单

- **问题**：物理符号系统假说包含哪两个核心论断？
- **参考答案**：充分性论断认为物理符号系统具备产生通用智能行为的充分手段；必要性论断认为任何表现通用智能的系统本质上都必须是物理符号系统。
- **预期来源**：第 29 页，第二章 2.1.1。
- **检索关键词**：PSSH、充分性、必要性。

### HA-004｜发展史｜中等

- **问题**：教程为什么用“问题驱动”的视角解释智能体范式演进？
- **参考答案**：新范式通常为解决上一代的核心痛点而出现，同时又引入新的局限，后续范式继续解决这些问题，形成迭代演进。
- **预期来源**：第 29 页，第二章开篇。
- **检索关键词**：演进阶梯、问题驱动、局限。

### HA-005｜LLM 基础｜简单

- **问题**：N-gram 模型使用了什么近似假设？
- **参考答案**：使用马尔可夫假设，把下一个词的概率近似为只依赖前面有限个词，而不是完整历史。
- **预期来源**：第 50 页，第三章 3.1.1。
- **检索关键词**：N-gram、马尔可夫假设、上下文窗口。

### HA-006｜LLM 基础｜中等

- **问题**：Bigram 与 Trigram 对上下文依赖的假设有什么区别？
- **参考答案**：Bigram 假设当前词只依赖前一个词；Trigram 假设当前词依赖前两个词。
- **预期来源**：第 50 页，第三章 3.1.1。
- **检索关键词**：Bigram、Trigram、条件概率。

### HA-007｜Agent 范式｜简单

- **问题**：教程介绍的三种经典智能体架构范式分别是什么？
- **参考答案**：ReAct、Plan-and-Solve 和 Reflection。
- **预期来源**：第 76 页，第四章开篇。
- **检索关键词**：ReAct、Plan-and-Solve、Reflection。

### HA-008｜Agent 范式｜中等

- **问题**：ReAct、Plan-and-Solve 与 Reflection 在工作方式上的核心区别是什么？
- **参考答案**：ReAct 交替推理与行动并动态调整；Plan-and-Solve 先生成完整计划再执行；Reflection 通过自我批判和修正优化结果。
- **预期来源**：第 76 页，第四章开篇。
- **检索关键词**：推理行动、先规划后执行、反思修正。

### HA-009｜工程实践｜中等

- **问题**：为什么教程认为亲手从零实现经典 Agent 范式仍有学习价值？
- **参考答案**：可以理解模型输出解析、工具失败重试和防止死循环等底层机制，暴露工程挑战，并获得超越框架默认能力的定制能力。
- **预期来源**：第 76 页，第四章开篇。
- **检索关键词**：重复造轮子、错误重试、死循环、系统设计。

### HA-010｜低代码平台｜简单

- **问题**：低代码 Agent 平台的四项核心价值是什么？
- **参考答案**：降低技术门槛、提升开发效率、提供更好的可视化与可观测性、沉淀标准化与最佳实践。
- **预期来源**：第 107 页，第五章 5.1.1。
- **检索关键词**：低代码、可观测性、标准化。

### HA-011｜低代码平台｜中等

- **问题**：教程如何界定低代码平台与纯代码开发的关系？
- **参考答案**：低代码不是取代代码，而是提供更高层抽象，让使用者更聚焦业务逻辑；从零编码仍适合深入学习和高度定制。
- **预期来源**：第 107 页，第五章 5.1.1。
- **检索关键词**：高层抽象、业务逻辑、纯代码。

### HA-012｜框架设计｜简单

- **问题**：一个 Agent 框架通常会抽象和封装哪些共性工作？
- **参考答案**：主循环、状态管理、工具调用、日志记录等通用工作。
- **预期来源**：第 150 页，第六章 6.1。
- **检索关键词**：Agent Loop、状态管理、工具调用、日志。

### HA-013｜框架设计｜中等

- **问题**：成熟 Agent 框架如何实现模型层、工具层和记忆层的解耦？
- **参考答案**：模型层统一模型交互并支持替换；工具层提供标准定义、注册和执行接口；记忆层独立处理短期和长期记忆策略。
- **预期来源**：第 150 页，第六章 6.1.1。
- **检索关键词**：Model Layer、Tool Layer、Memory Layer。

### HA-014｜自建框架｜中等

- **问题**：教程列出的成熟 Agent 框架四类局限是什么？
- **参考答案**：过度抽象带来的复杂性、快速迭代造成的 API 不稳定、核心逻辑黑盒化、依赖关系复杂和潜在冲突。
- **预期来源**：第 183 页，第七章 7.1.1。
- **检索关键词**：过度抽象、API 变更、黑盒、依赖冲突。

### HA-015｜自建框架｜中等

- **问题**：从“框架使用者”转向“框架构建者”能获得哪些能力？
- **参考答案**：深入理解 Agent 工作原理、获得实现与调优的控制权，并培养模块化、接口抽象和错误处理等系统设计能力。
- **预期来源**：第 183 页，第七章 7.1.1。
- **检索关键词**：构建者、控制权、系统设计。

### HA-016｜Memory｜简单

- **问题**：感觉记忆、工作记忆和长期记忆在持续时间与职责上有什么区别？
- **参考答案**：感觉记忆约 0.5–3 秒，临时保留感官输入；工作记忆约 15–30 秒、容量有限，服务当前任务；长期记忆持续时间长、容量近乎无限。
- **预期来源**：第 230 页，第八章 8.1.1。
- **检索关键词**：Sensory Memory、Working Memory、Long-term Memory。

### HA-017｜Memory｜中等

- **问题**：长期记忆中的程序性记忆与陈述性记忆如何区分？
- **参考答案**：程序性记忆保存技能和习惯；陈述性记忆保存可用语言表达的知识，进一步包含语义记忆与情景记忆。
- **预期来源**：第 230 页，第八章 8.1.1。
- **检索关键词**：程序性记忆、陈述性记忆、语义记忆、情景记忆。

### HA-018｜RAG｜中等

- **问题**：为什么 Agent 需要同时具备 Memory 与 RAG，而不能只依赖 LLM 参数知识？
- **参考答案**：Memory 保存交互历史与经验，RAG 从外部知识中检索可更新、可追溯的证据；二者共同缓解无状态、知识过时和缺少私域信息的问题。
- **预期来源**：第 230 页，第八章开篇。
- **检索关键词**：记忆系统、检索增强生成、历史经验。

### HA-019｜上下文工程｜简单

- **问题**：上下文工程关注的核心工程问题是什么？
- **参考答案**：在每次模型调用前，以可复用、可度量、可演进的方式拼装与优化输入上下文，使模型输出更正确、鲁棒和高效。
- **预期来源**：第 277 页，第九章开篇。
- **检索关键词**：Context Engineering、正确性、鲁棒性、效率。

### HA-020｜上下文工程｜中等

- **问题**：HelloAgents 的 GSSC 上下文流水线由哪四个阶段组成？
- **参考答案**：Gather、Select、Structure、Compress，即收集、选择、结构化与压缩。
- **预期来源**：第 277 页，第九章开篇。
- **检索关键词**：GSSC、ContextBuilder。

### HA-021｜通信协议｜简单

- **问题**：MCP、A2A 和 ANP 分别解决什么通信问题？
- **参考答案**：MCP 标准化 Agent 与工具的通信；A2A 支持 Agent 之间点对点协作；ANP 用于构建与发现大规模 Agent 网络。
- **预期来源**：第 334 页，第十章开篇。
- **检索关键词**：MCP、A2A、ANP。

### HA-022｜MCP｜中等

- **问题**：连接多个 MCP Server 时，为什么要给每个 MCPTool 使用不同名称？
- **参考答案**：名称会作为自动展开工具的前缀，可避免不同服务器中同名工具发生冲突。
- **预期来源**：第 350 页，第十章 MCP 工具自动展开。
- **检索关键词**：MCPTool、工具前缀、名称冲突。

### HA-023｜Agentic RL｜中等

- **问题**：教程如何把基于 LLM 的数学解题 Agent 映射为强化学习问题？
- **参考答案**：Agent 是基于 LLM 的推理系统，环境是问题与验证器，状态是题目和已有推理步骤，行动是下一步推理或答案，奖励由答案正确性给出。
- **预期来源**：第 383 页，第十一章 11.1.1。
- **检索关键词**：状态、行动、环境、奖励、Agentic RL。

### HA-024｜SFT｜中等

- **问题**：为什么在进行 Agentic RL 前通常先做 SFT？
- **参考答案**：SFT 先教会模型任务格式和基本推理模式，建立合理基线并缩小强化学习的探索空间。
- **预期来源**：第 400 页，第十一章 11.3.1。
- **检索关键词**：SFT、输出格式、基线、探索空间。

### HA-025｜Agent 评估｜简单

- **问题**：系统化 Agent 评估需要回答哪三个基本问题？
- **参考答案**：Agent 是否具备预期能力、在不同任务上表现如何、与其他 Agent 相比处于什么水平。
- **预期来源**：第 437 页，第十二章开篇。
- **检索关键词**：预期能力、任务表现、横向比较。

### HA-026｜工具调用评估｜中等

- **问题**：BFCL 评估器为什么使用 AST 匹配，而不是简单字符串匹配？
- **参考答案**：它需要比较函数调用的结构与参数语义，并兼容 JSON、代码块等不同表达形式；AST 匹配比字符串完全一致更准确。
- **预期来源**：第 452 页，第十二章 BFCL 评估。
- **检索关键词**：BFCL、AST、函数调用提取。

### HA-027｜人工评估｜中等

- **问题**：教程的人工验证流程包含哪些评分维度与结果状态？
- **参考答案**：评分维度包括正确性、清晰度、难度匹配和完整性；状态包括 approved、rejected、needs_revision，并可添加评论。
- **预期来源**：第 476 页，第十二章人工验证。
- **检索关键词**：人工验证、评分、approved、needs_revision。

### HA-028｜多 Agent 应用｜中等

- **问题**：智能旅行助手为什么使用多个专业 Agent 协作，而不是一个 Agent 包办所有任务？
- **参考答案**：把复杂规划拆成景点、天气、酒店、路线或预算等更简单的专业任务，使每个 Agent 聚焦专长，并便于后续扩展。
- **预期来源**：第 495 页起、第 510 页，第十三章。
- **检索关键词**：旅行助手、多 Agent、任务分解。

### HA-029｜深度研究｜中等

- **问题**：深度研究 Agent 需要哪三项核心能力？
- **参考答案**：问题剖析与查询拆解、多轮信息采集和去重整合、基于阶段结果反思知识空白并生成结构化总结。
- **预期来源**：第 532 页，第十四章开篇。
- **检索关键词**：问题剖析、多轮采集、反思总结。

### HA-030｜实战设计｜中等

- **问题**：赛博小镇中的智能 NPC 系统包含哪些核心能力？
- **参考答案**：自然语言对话、短期与长期记忆、随互动变化的好感度、2D 场景交互和实时日志。
- **预期来源**：第 574 页，第十五章开篇。
- **检索关键词**：NPC、记忆、好感度、实时日志。

## 评估边界

- 这 30 题覆盖教程主要章节，适合做第一版回归集，但不足以宣称整个系统的“准确率”。
- Recall@K 只判断正确来源是否进入前 K 条，不评价最终生成答案是否忠实。
- 建议后续扩展到至少 100 题，并加入无答案题、跨页题、跨文档题、相似干扰题与时间敏感题。
- 若一题允许多个正确页，应在评估数据结构中支持多个相关 Chunk，并使用分级相关性计算 nDCG。
