# KUN 3 分钟面试演示脚本

## 0:00-0:20｜业务问题

“我的资料分散在本地 PDF、Word、Excel 和图片中。KUN 的目标不是让模型泛泛聊天，而是让回答能回到具体资料，同时把工具调用、Memory 和失败状态展示出来。”

## 0:20-1:00｜导入与索引

1. 导入一份无敏感信息的公开或自制文档。
2. 展示解析、Chunk、Embedding 和索引状态。
3. 说明原文件不会被覆盖，索引前有确认，Embedding 元数据会记录模型和维度。

## 1:00-1:45｜带引用的复杂问答

1. 提问一个需要跨段落或跨页检索的问题。
2. 展示流式回答、页码/标题引用和引用预览。
3. 打开 RAG 实验室，展示 Recall@K、MRR、nDCG、平均延迟、P95 和逐题 Bad Case。

面试表达：“Recall 只说明正确来源进入 Top K，不代表最终回答一定正确；所以我另外保留引用定位成功率，并对未命中问题逐题分析。”

## 1:45-2:25｜Tool 调用与权限边界

1. 打开 Tool 中心，展示工具的参数、权限、超时、联网范围和确认要求。
2. 触发一个只读 Tool，展示 Tool Trace。
3. 说明写入、导出、Memory 变更和索引重建必须经过确认，模型不能自行获得 Tool 权限。

## 2:25-2:50｜Memory 与失败状态

1. 发送一条明确的“请记住”消息，展示待确认或已确认状态。
2. 关闭一个 Provider 或联网能力，展示明确的 unavailable/degraded 状态。
3. 说明 Memory-only 回答不会伪造文档引用。

## 2:50-3:00｜收束

“这个项目最想证明的是：我不仅会调用模型，也会把 Agent 的状态、检索、权限、可观测性和评测连成一个可解释的应用工程闭环。”

## 演示前检查

- 使用脱敏、自制或公开许可资料；不要展示个人简历、API Key、真实医疗数据或企业内部资料。
- 评测数据集、模型版本、机器环境和日期已经记录。
- 至少准备一个真实 Bad Case，并能解释下一步会改 Chunk、检索融合、Rerank 还是引用定位。
- 演示失败时直接说明失败原因和降级模式，不临时修改结果或口头补造指标。
